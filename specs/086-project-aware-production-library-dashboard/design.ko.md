# 디자인: 프로젝트 인식형 제작 라이브러리 대시보드

Issue: `086-project-aware-production-library-dashboard`
상태: 승인
승인자: Dongwon Lee, 2026-07-10
영문 정본: `design.md`
프로토타입: `prototype.html`

## 승인 결정

기존 ModuFlow 생성형 대시보드를 시각적으로 재설계하지 않고 확장합니다. 현재 제목, 시스템 폰트, 파란 활성 탭, 둥근 필터, 흰색 테이블, 테두리, 배지, 하단 정보 패널을 유지합니다.

제작 기록 상세는 오른쪽 고정 패널이 아니라 딤 처리된 모달로 엽니다. 기존 테이블 폭을 유지하면서 긴 제작 이력을 읽기 위한 공간을 확보하기 위한 결정입니다.

## 기존 UI 유지 기준

- 폰트: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`; macOS에서는 SF Pro로 표시됩니다.
- 페이지: 흰 배경, 20px 여백, 19px 제목.
- 탭: 기존 둥근 중립 버튼을 유지하고 활성 탭은 `#2a78d6`과 흰 글자를 사용합니다.
- 컨테이너: 기존 1px `#ddd` 테두리와 8px radius를 사용합니다.
- 테이블: 기존 헤더, 행 구분선, 파란색 hover/선택 상태를 유지합니다.
- 상태: 기존 배지와 chip 형태를 사용하며 승인 지침은 초록, 검토 상태는 노랑 계열로 구분합니다.
- 구현 시 기존 다크 모드 동작을 유지합니다.

새 브랜드 헤더, KPI 카드 행, 사이드바, 장식용 그라디언트, 별도 내비게이션은 추가하지 않습니다.

## 화면 구조

### 제목과 프로젝트 선택

기존 `ModuFlow 프로젝트 뷰` 제목은 왼쪽에 그대로 둡니다. 오른쪽에 간결한 `프로젝트` 선택기를 추가합니다.

단일 프로젝트 모드에서는 프로젝트 이름 또는 비활성 선택기로 표시할 수 있지만, 내부적으로는 다중 프로젝트와 같은 전역 프로젝트 상태를 사용합니다. 포트폴리오 모드는 등록 프로젝트와 `전체 프로젝트`를 표시합니다.

### 탭

기존 탭에 두 화면만 추가합니다.

1. 이슈 DB
2. 이슈 그래프
3. 지식 그래프
4. 제작 기록
5. 플레이북

생성 시각은 공간이 있으면 오른쪽에 표시하고 모바일에서는 다음 줄로 이동합니다.

### 프로젝트 요약

탭 아래 한 줄에 선택 프로젝트의 active/review 수, 제작 기록 수, 플레이북 수 또는 검토 후보, 다음 명령만 표시합니다.

`전체 프로젝트`는 프로젝트별 요약과 주의 항목만 보여줍니다. 제작 기록 본문, 내부 문장, 통합 지식은 표시하지 않습니다.

## 제작 기록 화면

기존 `.db`와 `.dbbar` 형태를 재사용합니다.

- 검색 대상: 제목, 판단, 실패, 재사용 패턴.
- 상태 필터: 전체, 승인, 검토, 완료 chip.
- 유형 필터: 기존 select 형태.
- 테이블 열: Production Record, Type, Channel, Status, Playbook.
- 행 hover와 선택은 기존 파란 계열 상태를 사용합니다.

실제 데이터가 많아지면 채널, 대상, 생명주기, 플레이북 상태 필터를 추가합니다. 좁은 화면에서는 컨트롤을 지나치게 줄이지 않고 다음 줄로 이동합니다.

## 제작 기록 상세 모달

제작 기록 행을 누르면 검정 42% 딤 위에 중앙 모달을 엽니다.

- 데스크톱: 최대 880px, 화면 좌우 32px 이상 여백.
- 높이: 화면 높이에서 64px를 뺀 값을 상한으로 하고 본문을 스크롤합니다.
- 모바일: 화면 전체 폭, 최대 92vh, 하단 고정, 위쪽 모서리만 둥글게 표시합니다.
- 닫기: 닫기 버튼, 딤 영역 클릭, Escape 키.
- 열 때 모달로 focus를 이동하고, 내부에 focus를 가두며, 닫을 때 원래 행으로 돌려보냅니다.
- 모달이 열린 동안 배경 스크롤을 막습니다.
- 상세 상태는 `replaceState`, 프로젝트/주 화면 이동은 `pushState`를 사용합니다.

모달에는 제목·날짜·유형·채널·대상·상태와 함께 아래 내용을 표시합니다.

1. Artifacts
2. Source Inputs
3. Decisions
4. Failed Attempts
5. Reusable Patterns
6. Do Not Repeat
7. 외부/고객 문장
8. 내부 보고 문장
9. Playbook Updates와 출처 링크

외부 배포 문장과 내부 보고 문장은 별도 테두리 영역으로 나눠 혼동을 막습니다.

## 플레이북 화면

기존 `.db` 테이블 형태를 사용합니다. 적용 범위, 버전, 승인 상태, 승인자/날짜, 재검토 상태, 출처 기록 수를 표시합니다.

`approved` 플레이북만 초록색 현재 지침으로 표시합니다. 후보와 보류 항목은 검토 대상으로만 보이며 현재 정책처럼 표시하지 않습니다. 상세은 제작 기록과 같은 모달 shell을 사용합니다.

## 프로젝트 전환

하나의 `selectedProjectId`가 모든 화면을 제어합니다. 프로젝트 변경은 다음 순서로 한 번에 처리합니다.

1. 등록 프로젝트 ID 검증
2. 열린 이슈·제작 기록·플레이북·지식 상세 닫기
3. 대상 프로젝트에서 유효하지 않은 필터 초기화
4. 헤더 요약과 모든 화면 payload 교체
5. 현재 탭 다시 렌더링
6. `?project=<id>#<view>` 갱신

탭별 별도 프로젝트 상태는 만들지 않습니다.

## 오류와 빈 상태

- 포트폴리오 미등록: 현재 프로젝트 모드는 계속 동작합니다.
- 읽을 수 없는 프로젝트: 해당 프로젝트만 경고하고 나머지는 유지합니다.
- 제작 기록/플레이북 없음: 관련 등록 명령을 포함한 기존 빈 패널을 표시합니다.
- URL 프로젝트 삭제: 기본 프로젝트로 이동하고 경고합니다.
- 산출물 누락: 기록을 숨기지 않고 주의 플래그를 표시합니다.
- payload 잘림: 생성 시각, 유지 수, 누락 수, 재생성 안내를 표시합니다.

## 반응형과 접근성

- 좁은 화면에서 제목과 프로젝트 선택기를 세로로 배치합니다.
- 탭, 요약, 필터는 잘리지 않고 줄바꿈합니다.
- 테이블은 텍스트를 억지로 줄이지 않고 가로 스크롤을 허용합니다.
- 모달은 `role="dialog"`, `aria-modal="true"`, 제목 연결을 제공합니다.
- 키보드 행 열기, Escape 닫기, focus trap과 focus 복귀를 검증합니다.
- 상태는 색상과 텍스트를 함께 사용합니다.

## 검증

- 데스크톱: 기존 이슈 DB, 제작 기록 테이블, 열린 상세 모달, 플레이북, 전체 프로젝트 요약.
- 모바일: 제목/프로젝트 배치, 탭·필터 줄바꿈, 테이블 스크롤, 하단 모달.
- 동작: 프로젝트 전환, URL 복원, 잘못된 프로젝트 fallback, 필터 초기화, 모달 focus, 빈 상태, 누락 링크 경고.
- 회귀: 기존 이슈 DB·이슈 그래프·지식 그래프·이슈 상세.
- 최종 게이트: 집중 테스트, 프로젝트 검증, `python3 scripts/release_check.py .`.

## 기각한 대안

- 오른쪽 고정 상세 패널: 기존 테이블 폭을 줄이고 기존 화면 변화가 큽니다.
- 새 앱 shell: 현재 ModuFlow와 시각적으로 분리됩니다.
- 기록별 독립 상세 페이지: 긴 글에는 좋지만 반복 비교 속도가 낮습니다.
- 브라우저 쓰기: Git 충돌·권한·검증·커밋 계약이 필요해 v1에서 제외합니다.

## 승인 결과

승인된 방향은 기존 ModuFlow UI에 전역 프로젝트 선택기, 제작 기록·플레이북 탭, 딤 처리 상세 모달만 추가하는 것입니다. 이 디자인은 재설계가 아니라 기존 대시보드의 점진적 확장입니다.
