## 핵심 설계

위키는 사람이 읽을 짧은 안내와 자료 ID 링크를 담고, 자료 목록은 메타데이터의 단일 기준이다. 기본 경로는 workspace/knowledge.md와 workspace/artifacts.md이며 실제 접근은 기존 canonical 프로젝트 경로를 사용한다. 원문은 기존 지식·메모리·문서·외부 위치에 남긴다.

조회 순서는 한 프로젝트 식별 → 위키/메타데이터 → ID 선택 → 선택한 원문이다. 필수 링크 누락과 선택적 비공개 원본 부재를 구분하며, 승인 상태·자료 최신성·원문 접근·커밋 공유 여부를 서로 바꾸어 해석하지 않는다. 원격 확인이나 자동 업로드는 하지 않는다.

자료 등록은 기존 103 저장 엔진에 제한된 artifact-register 동작을 추가하는 계획이다. 결과가 새로 생성되는 경우 결과/목록/이슈 링크가 함께 저장되어야 한다. 기존 파일·외부 원문은 수정하지 않는다. 현재 103은 이 작업을 지원하지 않고 공유 상태를 투영하므로, 기존 update 경로를 단순 호출해선 안 된다. C1에서 lifecycle/state/goal/loop/roadmap/dashboard 바이트 불변과 실패 복구를 검증한다.

## 함께 승인할 가정

1. **형식**: 자료 목록은 Markdown 안의 항목별 JSON 블록을 기준으로 한다. 표는 추후 읽기 전용 표시에서 제공할 수 있다. 별도 JSON DB를 두지 않는다.

2. **시점**: 기준일/기간과 갱신일을 분리한다. 명시한 review_after를 지났을 때 stale로 판단하고 미지정은 unknown이다. 임의의 30/90일 규칙을 적용하지 않는다.

3. **쓰기 경계**: 자동 다중 파일 등록에는 실제 소유 이슈가 필요하다. 빈 프로젝트 초기화는 기존 누락 파일만 생성하는 방식이며 별도 다중 파일 원자성을 주장하지 않는다. 기존 미배정 초안은 검토 후 수동 정리가 가능하다.

권고: 위 세 가정을 포함해 명세·계획을 한 번에 검토한다. 구현 승인 전에는 작업을 시작하지 않는다. 개별 화면·분석 실행기는 이번 승인의 범위가 아니다.

## 086·091·092에 넘길 계약

- 086/092: `moduflow.artifact-registry-read.v1` envelope를 한 프로젝트씩 읽는다. registry v2 project_id, 안정 artifact_id, 요약/read_when/기간/상태/원본 위치와 분리된 진단을 표시할 수 있다. 모든 프로젝트 원문을 한 HTML에 담지 않는다.
- 091: `(project_id, artifact_id, snapshot_commit, source locator, recorded state)`를 실행 입력 참조로 남긴다. 승인된 자료라는 기록은 실행 검증 통과가 아니다. 원본 접근 불가·미성숙 분석·실행 종료 같은 091 상태는 이 계약과 별개다.
- 명시적 루트 호환 조회에 project_id가 없으면 null/unbound로 반환한다. 이를 worktree 절대경로로 대체하지 않고 교차 프로젝트/분석 실행 전에 실제 식별을 요구한다.
- proposed API는 아직 구현되지 않았다. 086은 문서만 참조하고, 확정 전 별도 파서나 UI 코드를 만들지 않는다.
