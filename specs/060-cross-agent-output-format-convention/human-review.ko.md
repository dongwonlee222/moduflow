# ModuFlow 공통 출력 규칙 — 이슈 060 후속 검토

## 왜 필요한지

사용자가 구현 내용보다 먼저 “왜 이 일을 하는지” 이해할 수 있어야 합니다. 이 설명 방식은 특정 채팅의 기억이나 개발 저장소 규칙에 머물지 않고 ModuFlow를 쓰는 다른 프로젝트에도 전달돼야 합니다.

## 해결해야 할 문제

기존 PR·작업 보고는 변경 파일과 테스트부터 설명하고 실제 문제·사용자 효과를 빠뜨릴 수 있었습니다. 자동 PR 생성기의 Purpose도 해당 이슈의 목적이 아니라 PR 절차를 설명했습니다. 개발용 AGENTS.md에만 저장한 규칙은 설치된 플러그인 명령에 연결되지 않았습니다.

## 기대 효과

**왜 필요한지 → 해결해야 할 문제 → 기대 효과 → 구현·검증** 순서로 내용을 읽게 됩니다. 사용자가 목적을 다시 물어야 하는 상황을 줄이는 것이 기대 효과이며, 개선 폭을 측정했거나 모든 AI가 반드시 준수한다고 보장하는 것은 아닙니다.

## 변경 내용

- 배포 패키지에 포함되는 공통 규칙: `docs/output-format.md`.
- ModuFlow 진입·산출물 스킬과 PR·보고·공유·상태·주간 명령에서 공통 규칙을 참조합니다.
- 자동 PR/한국어 검토 문서도 목적·문제·기대 효과를 먼저 생성합니다.
- 선택한 프로젝트의 이슈를 먼저, 해당 명세를 필드별 보완 근거로 읽습니다. 근거가 없으면 “미기록”으로 남깁니다.
- 짧은 상태 보고는 간결하게 유지합니다. JSON/MCP 스키마와 승인·권한·상태 전환은 변경하지 않습니다.
- 출력 동작 변경의 소스 버전은 `0.3.56`으로 준비합니다. 실제 배포·설치 버전이 올라갔다는 뜻은 아닙니다.
