### 1. converge가 44커밋 중 1개만 수집 — 확인됨, 중요 (기존 결함)

`product-review.md` 5단계는 converge를 **"최종 증거 단계"**라고 부릅니다. 그런데 이 브랜치에서는 거의 눈을 감고 돕니다.

리뷰 시점 실측:

- 수집 커밋: **44개 중 1개**
- 수집 파일: **7개** — 상태 파일, 이슈 파일, spec 뿐
- **구현 파일 0개** — `project_issue_schema.py` 2,540줄, 컨슈머 8곳 변경, 테스트 전부 빠짐
- `errors`: `[]` ← **아무 경고도 없음**

원인은 **두 모듈이 "이 커밋은 어느 이슈 것인가"를 서로 다르게 답하는 것**입니다.

| 모듈 | 인식하는 근거 |
| --- | --- |
| `linkage_check.py` | 트레일러, **브랜치명** |
| `project_converge.py` | 트레일러, 머지 커밋 제목 |

`project_converge.py`에는 브랜치 폴백이 없습니다. 이 브랜치 커밋 43개엔 `Issue:` 트레일러가 없어서, 트레일러가 있는 1개만 잡힙니다. 같은 브랜치인데 linkage 게이트는 브랜치명 폴백 덕에 44개를 다 인식하고 통과합니다.

리뷰 도중 제가 트레일러 붙은 커밋을 하나 넣자 수집량이 1→2로 늘어, 원인이 정확히 확인됐습니다.

**093의 회귀가 아닙니다.** 093은 이 두 파일을 건드리지 않았습니다(`git diff`로 확인). 기존에 있던 결함이 큰 브랜치를 리뷰하면서 드러난 것입니다.

→ **머지를 막지 않습니다.** 다만 **이번 리뷰의 converge 증거는 못 씁니다.** 그래서 판정 근거를 테스트·릴리스 게이트·직접 코드 읽기로 대체했습니다. 별도 이슈 **095**로 등록했습니다.

### 2. 루프 기본값 전환 — 제 가설은 반증, 대신 진짜 크래시 발견 (수정 완료)

처음엔 `infer_issue_phase`의 기본값이 `status`에서 `execute`로 바뀐 게 **게이트를 우회하는 fail-open**이라고 의심했습니다. **직접 찔러본 결과 아니었습니다.**

| 조건 | 실제 결과 |
| --- | --- |
| 체크박스 없음 + 산출물 있음 + readiness 없음 | `execute` 단계지만 delegation 게이트가 차단 |
| 체크박스 없음 + 산출물 없음 | 구조 게이트가 `product:spec`으로 되돌림 |
| 파일 읽기 불가 | `ISSUE_SOURCE_UNREADABLE` → `product:doctor` |
| 깨진 심볼릭 링크 | 무해하게 정지 |

**모든 경로가 게이트에 걸립니다.** 기본값 전환은 "어느 단계인지 이름"만 바꿀 뿐 실행 권한을 주지 않습니다.

**대신 같은 지점에서 진짜 결함을 찾았습니다.** `<이슈id>.md`가 **디렉터리**로 만들어져 있으면 루프가 통째로 죽습니다:

```
IsADirectoryError: Is a directory: 'issues/019-....md'
```

`list_normalized_issues()`가 "존재하지만 파일이 아닌" 경로를 **진단 없이 조용히 건너뛰어서**, 평가에서 이슈가 사라지고 루프가 자체 파일 읽기로 폴백하다 예외가 그대로 터집니다. fail-closed여야 할 자리에서 그냥 죽는 겁니다.

이건 **finding 1과 똑같은 "조용한 누락" 부류**이고, 이번엔 **093이 새로 만든 모듈 안에 있습니다.**

**수정 완료.** 기존 권한 오류 처리와 동일한 blocked 레코드를 만들어 `product:doctor`로 라우팅합니다. 회귀 테스트 4개 추가(스키마 2 + 루프 2), 루프 쪽 2개는 체크박스 없는 라우팅이 나중에 fail-open으로 변질되지 않도록 고정합니다.

### 3. 44커밋 중 43개에 `Issue:` 트레일러 없음 — 확인됨, 낮음 (프로세스)

`main`의 머지 이력은 `Issue: <id>` 트레일러를 씁니다. 이 브랜치는 `fix(093):` 형태만 쓰고 트레일러를 생략했습니다.

linkage 게이트가 통과하는 건 **오직 브랜치명 폴백 덕분**이라, 증거가 위치 의존적입니다:

- detached HEAD 워크트리에서 검사하면 **44개 전부 미연결로 실패** (제가 실제로 겪었습니다 — 이게 Codex 에러의 유력 후보이기도 합니다)

finding 1이 그 구체적 결과입니다.
