## 문제

소스 저장소·설치 패키지·사용자 프로젝트는 검사 대상이 다르다. 현재 패키지 검증은 `.git`이 없으면 소스 전용 파일 요구를 제외하는 부분 처리가 이미 있다. 남은 문제는 검사 모드를 `.git` 유무로 추정하고, Doctor가 설치 캐시를 프로젝트로 검사할 수 있다는 점이다.

또한 설치 목록과 캐시 폴더가 있다고 현재 프로세스가 그것을 실행하는 것은 아니다. MCP는 요청 때마다 파일에서 버전을 읽어 실행 중 파일이 바뀌면 실제 시작 시점과 다른 버전을 보고할 수 있다. 이슈에 적힌 `project_status.py`는 없으며, 실제 수정 대상은 `mcp_server.py`, `project_doctor.py`, 상태 명령 문서다.

## 목표

1. 소스·설치본·프로젝트 검사를 명시적으로 구분하고 기존 릴리즈 검사를 유지한다.
2. 패키지 출처, 특정 프로세스의 시작 정보, AI 호스트의 스킬 로딩 여부를 구분한다.
3. 출처 정보는 명시적 패키징·설치 때 기록하고, 조회 중에는 수정하지 않는다.
4. 합성 데이터 시뮬레이션과 패키지 실행 확인, 실제 호스트 확인을 구분한다.

## 제외 범위

프로젝트 경로·권한 재설계, 상태 트랜잭션 확대, 전체 설치 설정의 원자적 변경, Doctor의 모든 기존 문제 수정은 제외한다. 새 실행 엔진·스케줄러·감시 프로세스·DB·대시보드·회사 프로필·Spec Kit 업데이트도 제외한다. 조회 중 자동 설치·업데이트·재로딩·복구·발송은 하지 않는다. 회사 실데이터나 비공개 다른 프로젝트 정보는 테스트에 넣지 않는다.

## 사용자 시나리오

- 관리자는 소스 테스트·산출물·릴리즈 증거가 빠진 소스를 통과시키지 않는다.
- 설치본 사용자는 Git 이력과 전체 개발 테스트 없이 배포 파일을 검증한다.
- 프로젝트 사용자는 플러그인 위치와 작업 프로젝트 위치를 구분해 진단한다.
- A에서 시작한 MCP는 B가 설치돼도 A의 시작 스냅샷을 보고하고, B에서 새로 시작한 프로세스만 B를 보고한다.
- 오래된 설치본의 메타데이터 부재와 손상, 현재 호스트 로딩 정보 부재를 각각 구분한다.

## 검사 모드

| 진입점 | 모드 | 동작 |
|---|---|---|
| 패키지 검증 `--mode source` | 소스 | 기존 소스 필수 파일·릴리즈 게이트 유지 |
| 패키지 검증 `--mode installed` | 설치본 | 배포 런타임 파일·fixture·필수 근거 검사. 전체 개발 트리는 요구하지 않음 |
| 기존 모드 없는 호출 | 호환 auto | 기존 동작을 유지하되 추정 모드와 근거를 표시. 공식 명령은 명시적 모드로 전환 |
| Doctor | 프로젝트 | Git 상위 경로 탐색·프로젝트 해석·복구 검사 전에 설치본 오입력 차단 |

기존 결과 키는 유지하고 `validation_role`, `role_source`, `warnings`, `error_codes`를 추가한다. 설치본을 소스 검사에 넣으면 역할 오류로 종료하며, 통과시키려고 설치본 모드로 자동 변경하지 않는다.

ModuFlow 매니페스트와 설치 영수증/런타임 구성을 사용한다. 설치 영수증이 있으면 복사된 프로젝트 파일보다 우선한다. 영수증과 `.git`이 없는 패키지형 경로는 구형 배포 구성으로 판단할 수 있지만 설치·로딩 증거가 되지는 않는다. 애매하면 `TARGET_ROLE_AMBIGUOUS`와 명시적 패키지 검사 안내를 반환한다. 설치 영수증 없는 원본 저장소의 자체 프로젝트 진단과 일반 프로젝트 진단은 유지한다. 실행본을 찾기 위한 임의 상위 폴더·홈 탐색을 추가하지 않는다.

## 하나의 출처 정보 읽기 모듈

`scripts/runtime_provenance.py`가 정확한 패키지 경로의 매니페스트·영수증을 읽는다. `inspect_package()`는 파일 읽기만 수행하고, `capture_runtime()`은 진입점에서 패키지·프로세스 시작 정보를 한 번 캡처한다. MCP 요청마다 다시 읽지 않는다. 시작 관측이 없는 직접 함수 호출은 로딩 시각을 만들어 내지 않는다.

같은 모듈의 읽기 전용 JSON CLI를 상태 명령에서 사용한다. CLI 결과는 그 CLI의 실행본 정보이지 대화 호스트가 읽은 스킬 버전의 증거가 아니다.

`runtime_provenance` 내부 스키마는 `moduflow.runtime-provenance.v1`이다. 버전·경로·소스 커밋·dirty 여부·설치 시각·로딩 시각·실행 종류·호스트·세션과 필드별 근거·알 수 없는 이유·오류 코드를 제공한다. 기존 MCP 스키마와 Doctor 키는 유지한다.

영수증 버전은 해당 호스트의 배포 매니페스트와 일치해야 하고, `+` 앞 기본 버전은 정본 Claude 매니페스트와 일치해야 한다. 정상적인 Codex 빌드 접미사 차이는 오류가 아니다. 영수증이 없으면 해당 매니페스트 버전을 패키지 근거로만 표시하며 설치를 추정하지 않는다.

실행 종류는 CLI 프로세스, MCP 프로세스, 별도 증거가 있는 호스트 세션을 구분한다. `loaded_at`은 표시한 종류의 시작 관측 시각이며 설치 시각·mtime·현재 요청 시각으로 대신하지 않는다. 모르는 값은 `null`과 이유로 표시한다. MCP 버전과 출처 정보는 같은 시작 스냅샷을 사용한다.

## 변경하지 않는 패키지 출처 기록

준비 중인 배포본에만 `.moduflow-package.json`을 만든다. 버전·소스 커밋·dirty·설치 시각·배포 내용 해시·근거·알 수 없는 이유를 담는다. 소스 Git 조회는 명시적 패키징에서 주입 가능한 runner로 수행하며 런타임은 Git을 실행하지 않는다. dirty 소스의 커밋은 기준 커밋일 뿐 실제 배포 내용과 동일하다고 주장하지 않는다.

내용 해시는 정렬한 상대 경로와 파일 해시로 계산하며 영수증 자신과 인터프리터 캐시는 제외한다. 비공개 staging 폴더에서 같은 디렉터리 임시 파일에 기록·flush/fsync·원자 교체 후 검증한다. 실패 시 기존 설치본을 보존한다. 같은 버전의 기존 배포는 내용·영수증이 일치할 때만 재사용하고, 다르면 `PACKAGE_DESTINATION_CONFLICT`로 중단한다. 모든 설정·링크의 원자 갱신까지 확장하지 않는다.

조회 중 영수증을 수정하지 않는다. 구형 배포의 메타데이터 부재는 경고와 명시적 미확인으로 처리한다. 손상·버전 불일치·잘못된 시각은 `PROVENANCE_INVALID`로 설치본 검사에 실패하지만, 무관한 사용자 프로젝트의 산출물이 잘못됐다고 표시하지 않는다. 영수증은 로컬 빌드 근거이지 서명·변조 방지 증명이 아니다. 다른 호스트가 영수증 없이 설치했다면 임의로 고치지 않고 구형/미확인으로 보고한다.

## 기존 버전 차이 감지 유지

065의 `checked`, `stale`, `recommendations`는 유지한다. 확인된 패키지 경로는 공통 모듈로 읽고, 호스트 설치 목록과 캐시 디렉터리 이름만 있는 경우 설치 목록 근거로 표시한다. 활성 실행본으로 승격하지 않는다. 읽기·파싱 실패는 진단으로 남기며, 자동 업데이트나 다른 프로젝트 탐색은 추가하지 않는다.

## 검토한 대안

1. 권장: 기존 진입점에 역할을 명시하고 공통 읽기 모듈 하나를 추가한다.
2. 소스 버전이나 최신 캐시명만 표시: 수정은 적지만 실제 실행본 혼동을 해결하지 못한다.
3. 실행 등록 서버·감시·자동 재로딩 추가: ModuFlow의 실행 책임을 늘리므로 제외한다.

## 완료 조건

- AC1: 소스 필수 검사는 유지하고 설치본은 Git·전체 테스트 없이 통과한다. 필수 런타임 파일 누락은 실패한다.
- AC2: 설치본을 Doctor에 넣으면 프로젝트 해석 이전에 차단한다. 빈 프로젝트와 원본 자체 프로젝트는 정상적인 프로젝트 진단을 받는다.
- AC3: 상태·Doctor·MCP가 같은 출처 스키마를 제공하고 모르는 값마다 null과 이유가 있다.
- AC4: 원자적 출처 기록과 기존 캐시 보존을 검증한다. 쓰기/이름 변경 실패 및 같은 버전 충돌을 테스트한다.
- AC5: 기존 프로세스의 시작 스냅샷과 새 프로세스를 구분한다. 호스트 스킬 재로딩을 추정하지 않는다.
- AC6: 065의 설치 목록·버전 차이 경고를 유지하고 실제 로딩 증거와 혼동하지 않는다.
- AC7: 소스·설치본·구형·누락/손상·실행본 불일치·오입력·두 프로젝트·별도 worktree·중단된 설치·무쓰기/무네트워크를 시뮬레이션한다.
- AC8: 단위 테스트·시뮬레이션·배포본 CLI/MCP 실행·원격 반영·배포·실제 Codex/Claude 확인을 분리한다. 확인 못 한 것은 미확인으로 남긴다.
