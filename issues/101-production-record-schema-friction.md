# Issue 101: Production Record Schema Rejects Four Times Before First Success

**Status: backlog** — created 2026-08-08.
**Priority: p2**
**Blocked-by:**

## Summary

Writing a first `product:production` record required four validate-fix cycles. Every rejection was a format rule that is enforced but never shown — not in the generated template, not in the error, not in the command doc.

## Source

- Type: finding from first real use (2026-08-08)
- Context: recording a failed RAG re-chunking attempt as a production record + playbook

## Problem

The record generated by `--new-record` contains section headers and `None recorded` placeholders. It does not show the line format each section requires. `--validate` then rejects, one rule at a time.

**Four cycles, in order:**

| # | Error | Actual rule | Discoverable? |
| --- | --- | --- | --- |
| 1 | `invalid artifact entry` | `- [label](target) — variant · audience` | only by reading `ARTIFACT_RE` in the script |
| 2 | `invalid artifact entry` (again) | **every line must match** — a `>` note in the section is a hard error | no |
| 3 | `invalid playbook update` | `- <playbook_id> — <state>` | only by reading `PLAYBOOK_UPDATE_RE` |
| 4 | `missing section: Approved Copy Blocks` | playbooks need all 6 sections | template exists but `--new-record` doesn't scaffold playbooks |

Each cycle costs a validate round trip. Errors name *what* failed, never *what shape was expected*.

A fifth issue is structural: `dangling playbook update` requires the playbook file to exist first, but there is no `--new-playbook`. The record references a playbook that must be hand-created from a template the user has to find.

## Scope

- `--new-record` — write one commented example line per structured section instead of bare `None recorded`
- Validation errors — include the expected pattern in the message
- Add `--new-playbook` mirroring `--new-record`
- `commands/product-production.md` — document the line formats

## Do NOT touch

- The schema itself. Strictness is the point; discoverability is the gap.
- `External Copy` / `Internal Reporting Copy` sections (see 100 for the domain-fit question)

## Acceptance Criteria

1. A record created by `--new-record` shows the required line shape for `Artifacts` and `Playbook Updates` as a comment or example.
2. Every format rejection message contains the expected pattern, not only the offending line.
3. `--new-playbook <id>` creates a template-conformant playbook with all required sections.
4. A user following only `commands/product-production.md` — without reading any script — passes `--validate` on the first attempt. This is the measurable outcome.

## Global Constraints

- No schema relaxation. Same rules, surfaced earlier.
- Example lines must not themselves fail validation (comment them or make them valid).
