# Goal: 프로젝트와 LLM 사이의 연결고리

## 무엇

모두플로는 **프로젝트와 LLM 사이의 연결고리**다.
히스토리·메모리·이슈·로드맵·플레이북·프로세스·스킬을 한곳에 두어,
**다음 세션이 0에서 시작하지 않게 한다.**

프로젝트의 주요 내용 — 메일, 회의에서 나온 의사결정, 기타 자료와 정보 — 도
메모리 관리에 들어온다. **목적은 프로젝트가 잘 수행되는 것이다.**

모두플로는 이것들을 **보관하고 건네준다. 실행은 외부 도구가 한다.**
**LLM이 좋아지면 이 층은 거기에 맞춰 유동적으로 변한다.**

## 안 하는 것

아래 일곱 줄 중 다섯은 이전 목표 문서(2026-09-04)의 Constraints에서 그대로
옮겼다. 다른 데서 복원할 수 없는 결정들이다.

- **실행하지 않는다.** 두 번째 실행 런타임도, 스케줄러도, 큐도, Spec Kit 전체
  구현도 아니다. 플레이북과 프로세스를 **보관하고 건네줄 뿐** 돌리지 않는다.
- **메일·회의록·외부 자료는 가리키기만 한다** (`memory/references/`).
  원본은 저장소에 들어오지 않는다. 민감한 원본 데이터와 인증정보도 저장소 밖에
  둔다.
- **git 파일이 정본이다.** GitHub과 대시보드는 투영이다.
- **등록된 프로젝트만 본다.** 옆 폴더를 훑지 않고, 프로젝트 간 원본 기록을
  가로질러 검색하지 않는다.
- **원격을 자동으로 고쳐 쓰지 않고, 승인 없이 바깥에 공개하지 않는다.**
- **공용 플레이북 자동 승격, 승인자 자동 인가, 검증 없는 최종 상태 전이를
  하지 않는다.**
- **대시보드 데이터베이스를 두 번째로 만들지 않고**, 공유 HTML에 프로젝트 간
  비공개 내용을 담지 않는다.

## 이뤘다고 하려면

이동원이 2026-09-07에 정한 네 가지다.

1. **새 세션이 파일만 읽고 이어서 일한다.**
2. **다른 사람·다른 컴퓨터가 받아도 똑같이 동작한다.**
3. **무엇이 끝났고 왜 그렇게 정했는지 파일만 보면 안다.**
4. **LLM이 좋아지면 이 층이 거기에 맞춰 변한다** — 프로젝트 파일을 다시 쓰지
   않고.

> 4번은 "새 모델이 나와도 그대로 쓴다"고 제안했다가 받은 정정을 옮긴 것이다:
> 그대로가 아니라 **유동적으로 변하는 것**이 맞다.

"프로젝트가 잘 수행되는 것"은 목적이지 완료 조건이 아니다. 잴 수 없으므로 위
「무엇」에 두었다.

## 이슈를 거르는 법

이슈를 만들기 전에 묻는다 — **이걸 안 고치면 누가 무엇을 못 하는가?**

답이 위 「무엇」의 일곱 가지(히스토리·메모리·이슈·로드맵·플레이북·프로세스·
스킬) 중 어디도 막지 않으면, **모두플로 일이 아니다.**
답이 "아무도 막히지 않는다"이면 **이슈를 만들지 않는다.**

`## 안 고치면` 섹션이 이 답을 담는 자리이고,
`scripts/validate_project_artifacts.py`의 `SECTION_RULES`가 검사한다.
